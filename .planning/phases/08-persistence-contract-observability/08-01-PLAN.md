</objective>

  <action>
在 `internal/metricspersist` 内把“发生过 drop/写入失败”做成可复用、可查询的进程级状态：

- 在 `internal/metricspersist/health.go` 定义对外稳定的原因码 enum（字符串）：
  - `queue_full`
  - `writer_not_started`
  - `insert_failure`
  并定义 `PersistenceHealth`（至少包含 `Degraded bool`, `DroppedTotal uint64`, `LastDropAt time.Time/UnixNano`, `LastDropReason *DropReason`）。

- 提供 `GetPersistenceHealth(now time.Time) PersistenceHealth`：
  - `DroppedTotal` 为进程生命周期累计（不重置）。
  - `Degraded` 通过 `last_drop_at` 与 `quiet period` 计算（quiet period 用代码常量，例如 5m；不要引入新配置/参数）。
  - 静默期后 `Degraded` 自动变为 false（但 `DroppedTotal` 不清零）。

- 在 `internal/metricspersist/writer.go` 的关键丢弃路径记录 drop（必须可追踪，不允许静默）：
  - `!w.started.Load()` 的 drop => `writer_not_started`
  - queue 满 `default:` 分支 => `queue_full`
  - `db.Prepare(insertSQL)` 失败（即便理论上已通过 preflight，也要兜底记录）=> `insert_failure`
  - `stmt.ExecContext(...)` 返回 error => `insert_failure`（只记录 reason，不把 `error.Error()` 对外暴露；不要返回 SQL 字符串、路径、用户输入）

- 启动 fail-fast：把“writer goroutine Prepare 失败会静默退出”的坑修掉。
  - 在 `Start(db)`（或 `StartWriter`）中对 INSERT SQL 做一次 preflight `Prepare` 并立即 Close，失败则返回 error，确保 `cmd/server/main.go` 的启动链路能 `os.Exit(1)`。
  - 保持 request path 语义不变：`Enqueue` 仍然永不阻塞。

约束：drop 统计必须是低开销（避免在 enqueue hot path 打日志/做复杂分配）。
  </action>

在 management 查询的响应 envelope 上承载“best-effort persistence 健康状态”，并严格遵守默认输出不变：

- 在 `internal/api/handlers/management/metrics.go` 的 `metricsMeta` 增加指针字段（omitempty）：
  - `Persistence *metricsPersistenceMeta \`json:"persistence,omitempty"\``
  - `metricsPersistenceMeta` 最小字段集合：
    - `degraded`（bool，固定 true，因为只有 degraded 才输出该结构）
    - `dropped_total`（uint64）
    - `last_drop_at`（RFC3339 string，UTC）
    - 可选：`last_drop_reason`（*string 或 *DropReason，omitempty；仅输出 enum 值）

- 在 `GetMetrics` 中对三种 mode（request_id / percentiles / buckets）都统一“装饰 meta”：
  - 在构造 `meta := metricsMeta{...}` 后调用一个小函数（例如 `attachPersistenceMeta(&meta)`）
  - 该函数内部调用 `metricspersist.GetPersistenceHealth(h.nowUTC())`
  - 仅当 health.Degraded 为 true 时填充 `meta.Persistence`，否则保持 nil（保证默认 JSON 不增加字段）

 - 为测试提供可控注入点（避免全局单例导致测试串扰），同时避免“运行中可变 setter”带来的生产误用：
   - 在 `internal/api/handlers/management/handler.go` 的 `Handler` 增加 `persistenceHealth func(time.Time) metricspersist.PersistenceHealth`（默认指向 `metricspersist.GetPersistenceHealth`）
   - 仅允许“构造时注入”：给 `NewHandler(...)` 增加可选项（例如 `WithPersistenceHealthProvider(fn)`）来覆盖默认 provider；禁止在 handler 开始处理请求后再修改 provider（不新增 exported setter）。

安全边界：
- 禁止把 drop 的 request_id 列表或 SQL 错误原文塞进响应；只允许 enum 与聚合计数/时间。
- 仅在现有 management auth 边界内可见（本任务不改路由/鉴权逻辑）。
