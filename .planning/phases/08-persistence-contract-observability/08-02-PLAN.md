在 `internal/metricspersist/writer_test.go` 扩展测试，精确驱动并断言三类 drop 与恢复语义：

- 并发/顺序隔离策略（必须显式执行）：
  - `DroppedTotal` 是进程生命周期计数器，测试断言必须使用 baseline+delta（先取 `baseline := GetPersistenceHealth(now).DroppedTotal`，再断言 `DroppedTotal == baseline + N`），禁止依赖绝对值（例如 `DroppedTotal == 1`）。
  - 同一文件内新增的测试不要 `t.Parallel()`；通过 baseline+delta + `t.Cleanup(...)` 恢复全局/包级状态，确保任意顺序执行都稳定。

- 增加测试：`writer_not_started` drop
  - 在未调用 `StartWriter` 的情况下调用 `Enqueue`（需要 08-01 已让该路径 record drop）。
  - 调用 `GetPersistenceHealth(now)` 断言：`DroppedTotal` 基于 baseline 增加、`LastDropReason==writer_not_started`、`Degraded==true`。

- 增加测试：writer preflight 失败必须可见（启动可 fail-fast）
  - 打开一个全新的 SQLite DB，但**不执行** migrations（确保 `metrics` 表不存在）。
  - 调用 `StartWriter(db)`（或等价入口），断言返回 error。
  - 目的：锁定“Prepare 失败不会在 goroutine 内静默吞掉”，从而满足契约中“启动阶段不可用 => fail-fast（拒绝启动）”的前置条件。

- 增加测试：`queue_full` drop
  - 在包内测试中替换 `defaultWriter` 为一个小队列 writer（例如 queueSize=1），并把 `started` 置为 true 但不启动 run（避免消费队列）。
  - 连续 Enqueue 两次：第二次应触发 `queue_full`，并断言 health 记录。
  - 使用 `t.Cleanup(...)` 恢复 `defaultWriter`（避免影响其他测试）。

- 增加测试：`insert_failure` 可观测
  - 真实启动 writer：InitDB+Migrate+StartWriter。
  - 通过让 DB/stmt 在 writer 运行中变为不可用来触发 ExecContext error（例如 Close db 后 Enqueue，或其他确定性方式），并等待 health `LastDropReason==insert_failure`。

- 增加测试：quiet period 后 degraded 自动清除
  - 人工设置/触发一次 drop，拿到 `last_drop_at`。
  - 用 `GetPersistenceHealth(last_drop_at + quietPeriod + 1s)` 断言 `Degraded==false`（DroppedTotal 不变）。

约束：测试应避免依赖 wall-clock 抖动；尽量用注入的 now 或可控时间参数来断言 degraded。
