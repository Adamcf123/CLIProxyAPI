新增 `internal/metricsruntime/display.go`，实现不影响主链路的“旁路显示器”，要求：

- API 设计：
  - `StartLiveDisplay(state *RequestState) (stop func())`
  - stop 必须幂等；stop 后应输出一次最终汇总（或由调用方显式调用 `PrintSummary`）
- 输出位置：仅 `os.Stderr`；不得写入 `c.Writer` 或任何 HTTP 响应。
- 刷新策略：每秒 ticker 更新一次，输出同一行：
  - 使用 `\r` 回到行首 + ANSI 清行（`\033[2K`）
  - 内容建议包含：tracking_id（短截断）、elapsed、ttft（若已采集）、tps（若已计算/否则 --）、output_tokens（若已知/否则 --）
- 结束汇总：输出换行终止覆盖模式，打印 JSON 风格或 key=value 风格的单行汇总（便于复制/检索），字段至少包含：
  - tracking_id, provider, model, tps, ttft, tpot, input_tokens, output_tokens, duration_ms, status_code
  - 对于未知值使用 `null`/`--`，且要明确原因（例如 usage 缺失导致 tokens 不可用）。
- TTY 处理：只在 stderr 是 TTY 时启用“同行覆盖”，否则降级为不频繁的单行输出（仍每秒，但不要清行），避免污染非交互日志。

更新 `RequestState`：补齐 display 需要读取/展示的字段（例如 `StatusCode`、`RequestPath`、`LastError`、`OutputTokens`、`Metrics`）。

在所有调用 `h.ForwardStream(...)` 的 streaming handler 中接入 request state + display：

- 在进入 `ForwardStream` 前：
  - 创建 `state := metricsruntime.NewRequestState(streaming=true, requestedModel=<client model>)`（或等价构造）
  - `metricsruntime.AttachRequestState(c, state)`
  - `stop := metricsruntime.StartLiveDisplay(state)`；`defer stop()`
- 在 `ForwardStream` 返回之后（或 cancel 被调用之后）：
  - 将 `state.StatusCode`、`state.RequestPath` 等从 `gin.Context` 填充（如果 display/summary 依赖）
