新增 package `internal/metricslog`，提供专用指标落盘能力（不要复用 logrus 文本日志）：

- 定义 `MetricsLogLine`（types.go），字段对齐 CONTEXT 的“日志字段”：
  - tracking_id, provider, model
  - tps, ttft, tpot（用 *float64 以便缺失时编码为 null）
  - input_tokens, output_tokens, total_tokens（用 *int64 或 sql.NullInt64 风格，但 JSONL 里推荐指针）
  - duration_ms（*int64 或 int64，视是否可缺失）
  - request_path, status_code, error_info, timestamp
- `jsonl_writer.go` 实现：
  - 单 goroutine 持有文件句柄 + bufio.Writer + json.Encoder
  - 通过 buffered channel 接收 `MetricsLogLine`
  - 文件名：`logs/metrics-YYYY-MM-DD.jsonl`（目录不存在时 `os.MkdirAll("logs", 0o755)`）
  - 按天切换：日期变化时 close 旧文件、打开新文件（append 模式）
  - 写入策略：`enc.Encode(line)`（自带换行，天然 JSONL）
  - Flush：定时 flush（例如 1s）+ 关闭时 flush
  - 错误策略：写入/flush/rotate 失败都不能 panic；错误视为“写入失败”，静默丢弃该条并继续。
  - 入队策略：对调用方提供 non-blocking `Enqueue(line)`，队列满则直接丢弃（满足“主链路不阻塞”）。

注意：不引入新的业务开关参数；路径固定为 logs/metrics-YYYY-MM-DD.jsonl。

实现 `internal/metricsruntime/usage_plugin.go`：

- 定义 `MetricsPlugin` 实现 `sdk/cliproxy/usage.Plugin` 接口：`HandleUsage(ctx, record)`。
- 在 HandleUsage 内：
  - 从 `ctx.Value("gin")` 取 `*gin.Context`；若不存在则仍应落盘（provider/model/tokens/timestamp），但 TTFT/TPS/TPOT 可能为 null。
  - 若存在 gin context：读取 `metricsruntime.RequestState`（02-01 的 state）。
  - 用 `record.Provider`/`record.Model` + `state.Streaming` 组装 `metrics.MetricKey`。
  - 从 `record.Detail` 取 input/output/total tokens：
    - 当所有 token 均为 0 且 `record.Failed==false` 时视为“usage 缺失”，日志字段写 null。
  - 当 output_tokens 可用且 state 有足够时间戳（流式需要 first token）：
    - 构造 `metrics.RequestMetrics`（不依赖 StartRequest）：填充 TrackingID、Key、StartTime、FirstTokenTime（若有）、EndTime（用 time.Now 或从 state 取结束时间）
    - 调用共享的 `internal/metrics.TPSCollector.CompleteRequest(m, int(outputTokens))` 计算 TPS/TTFT/TPOT 并写入滑动窗口
    - 将结果回填到 `RequestState` 供 02-02 的结束汇总展示
  - 组装 `metricslog.MetricsLogLine` 并 `metricslog.Enqueue(line)`。

注册方式：复用现有 internal/usage 的 init 入口（避免新增 blank import）：
- 新增 `internal/usage/metrics_plugin.go`，在 init 中 `sdk/cliproxy/usage.RegisterPlugin(metricsruntime.NewMetricsPlugin(...))`。
- 保持 `internal/usage/logger_plugin.go` 的现有行为不变。

必要时对 `internal/runtime/executor/usage_helpers.go` 做最小改动以提升一致性：

- 注意：此处是“复用/修正现有归一化”，不是在 handler 层重写解析。
