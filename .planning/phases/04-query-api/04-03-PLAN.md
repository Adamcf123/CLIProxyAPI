<task type="auto">
  <name>Task 2: 在 GetMetrics 实现 mode=percentiles 聚合（success/failure 分开）</name>
  <files>
    - internal/api/handlers/management/metrics.go
  </files>
  <action>
    在既有 `GetMetrics` 中填充 `mode=percentiles` 分支（替换之前的 501）。

    1) SQL 读数据（参数化，避免拼接）：
       - 读取范围：[from,to)（from/to 为 RFC3339，SQL 内使用 `datetime(?)` 解析）。
       - 读取列：provider, model, streaming, status_code, error_info, tps, ttft, tpot, duration_ms。
       - 可选过滤：provider/model/streaming（若 query 参数提供）。

    2) 在 Go 侧聚合：
       - 固定分组 key：provider + model + streaming。
       - success/failure 切分规则（在 contract 中锁定）：
         - `success = status_code >= 200 AND status_code < 300 AND (error_info IS NULL OR error_info = '')`
         - 其余归为 failure。
        - 每个分组返回：
          - `count`：请求数（行数）。
          - 对每个指标（tps/ttft_ms/tpot_ms/duration_ms）：
            - 仅对非 NULL 样本计算 percentiles；若样本为空，percentiles 为 null。
            - `ttft_ms`/`tpot_ms` 必须输出毫秒整数，并锁定取整策略：
              - 必须复用 04-02 中引入的 `secondsToMillisInt` helper（禁止在 percentiles 分支内另写 `*1000` + cast）。

    3) 响应结构（本计划定稿，后续不再改动字段命名）：
       - `meta`: 复用 04-02 的 meta 字段，追加 `mode=percentiles`。
       - `success`: 数组，每个元素包含 `{provider, model, streaming, count, metrics:{...}}`。
       - `failure`: 同上。
       - `metrics` 内对每个指标输出：`sample_count`, `p50`, `p95`, `p99`（percentiles 允许 float；延迟类/Duration 必须 int ms）。

    4) 性能与正确性约束：
       - 不要在 SQLite 里实现 percentile（保持语义一致 + 代码可维护）。
       - NULL 不得当作 0。
  </action>
  <verify>
    运行 `go test ./...`。
  </verify>
  <done>
    `GET /v0/management/metrics?mode=percentiles&from=...&to=...` 返回 success/failure 两套分组结果，并包含 p50/p95/p99。
  </done>
