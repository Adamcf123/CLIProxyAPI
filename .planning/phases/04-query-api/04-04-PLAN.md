  <name>Task 1: 实现 mode=buckets（固定粒度 + UTC 对齐 + SQL 粗聚合）</name>
  <files>
    - internal/api/handlers/management/metrics.go
  </files>
  <action>
    在 `GetMetrics` 中填充 `mode=buckets` 分支（替换之前的 501 或占位）。

    1) bucket 参数与 preset：
       - query 参数名：`bucket`。
       - 允许集合（定稿）：`1m`, `5m`, `15m`, `1h`, `1d`。
       - 非法 bucket：400。

    2) 时间范围与对齐（UTC 自然边界定稿）：
       - 请求范围仍用 [from,to)（与 percentiles 一致）。
       - 计算并回显：
         - `effective_from`: floorToBucket(from.UTC())
         - `effective_to`: ceilToBucket(to.UTC())
         - `timezone`: "UTC"
       - 生成 bucket 时间轴：从 effective_from（含）到 effective_to（不含），步长为 bucket。

    3) SQL 聚合（避免递归 CTE，按 research 建议）：
        - 用 `unixepoch(created_at)` 计算 bucket_start（秒级对齐）。
        - success_flag 表达式（必须与 04-03 的 success/failure 规则一致，写死避免漂移）：
          - `CASE WHEN status_code >= 200 AND status_code < 300 AND (error_info IS NULL OR error_info = '') THEN 1 ELSE 0 END AS success_flag`
        - GROUP BY：provider, model, streaming, success_flag, bucket_start。
        - 聚合输出至少包含：
          - `count`（请求数）
          - `tps_avg`（AVG(tps)）
          - `ttft_avg`（AVG(ttft)）
          - `tpot_avg`（AVG(tpot)）
          - `duration_ms_avg`（AVG(duration_ms)）
        - 注意：ttft/tpot 是秒（REAL），最终输出必须转换为毫秒整数：
          - 必须复用 04-02 的 `secondsToMillisInt` helper（禁止在 buckets 分支内另写 `*1000` + cast）。

    4) Go 侧回填空 buckets（locked decision 强制）：
       - 对每个返回的分组（provider+model+streaming + success/failure）都生成完整 bucket 序列。
       - 缺失 bucket：输出 `{start: <rfc3339>, count:0, metrics: nulls}`。
       - 有数据 bucket：输出 count 与各 avg 指标（无样本则为 null）。

    5) 响应结构（与 percentiles 保持一致的顶层）：
       - `meta`: mode=buckets + bucket + timezone + requested/effective + filters。
       - `success`: 数组，每个分组包含 buckets 数组。
       - `failure`: 同上。
  </action>
