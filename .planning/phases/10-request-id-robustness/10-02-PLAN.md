## Key Insight

SQLite 的 `ON CONFLICT DO NOTHING` 在冲突时返回的影响行数为 0。通过检查 `sql.Result.RowsAffected()` 可以区分：
- RowsAffected == 1: 正常插入
- RowsAffected == 0: 冲突（或无效数据）

结合 request_id 的唯一性约束，RowsAffected == 0 可判定为 request_id 冲突。

    // ... validation ...

修改为：
```go
insert := func(r MetricRecord) {
    if r.RequestID == "" || r.Provider == "" || r.Model == "" {
        return
    }
    streaming := int64(0)
    if r.Streaming != nil && *r.Streaming {
        streaming = 1
    }
    ctx, cancel := context.WithTimeout(context.Background(), insertTimeout)
    defer cancel()
    
    // Use ExecContext and check RowsAffected to detect conflicts
    result, err := stmt.ExecContext(
        ctx,
        r.RequestID,
        r.Provider,
        r.Model,
        streaming,
        r.TPS,
        r.TTFT,
        r.TPOT,
        r.InputTokens,
        r.OutputTokens,
        r.TotalTokens,
        r.DurationMS,
        r.StatusCode,
        r.ErrorInfo,
    )
    if err != nil {
        recordPersistenceDrop(DropReasonInsertFailure, time.Now().UTC())
        return
    }
    
    // Detect request_id conflict: ON CONFLICT DO NOTHING returns 0 rows affected
    rowsAffected, err := result.RowsAffected()
    if err == nil && rowsAffected == 0 {
        recordPersistenceDrop(DropReasonRequestIDConflict, time.Now().UTC())
    }
}
```

关键变更：
1. 将 `_, err := stmt.ExecContext(...)` 改为 `result, err := stmt.ExecContext(...)`
2. 在 err == nil 后，调用 result.RowsAffected() 检查影响行数
3. 如果 rowsAffected == 0，记录 DropReasonRequestIDConflict
4. 保持原有的错误处理逻辑（err != nil 时记录 DropReasonInsertFailure）
