  <name>Task 1: 修复 rg_secrets_guard（扫描 artifacts 且可审计）</name>
  <files>

    .planning/phases/11-runtime-validation/scripts/run_baseline.sh
    .planning/phases/11-runtime-validation/scripts/run_edge_cases.sh
  </files>
  <action>
    目标：secrets guard 必须满足三点：
    - 扫描覆盖 artifacts（不被 `.gitignore` 绕过）
    - 只扫描“可能包含文本 secrets 的文件”，避免对 SQLite/WAL 等二进制误报/性能问题
    - 产出可审计的 scan 输出文件（报告可引用）

    1) 修改 `scripts/lib.sh:rg_secrets_guard`：
       - 使用 `rg --no-ignore`（必要时加 `--hidden`）确保 artifacts 内的被 ignore 文件也会被扫描。
       - 使用 globs 限定扫描范围：只扫 `*.log`, `*.txt`, `*.tsv`, `*.json`, `*.md`, `*.out`, `*.sse`（按本 phase 产物类型）
       - 模式要更精确以避免误报：
         - 头行用锚定：`^Authorization:` 与 `^X-Management-Key:`
         - API key 形态：`sk-[A-Za-z0-9]{16,}`（保留占位 `sk-dummy` 不触发）
       - 输出：把 scan 命令与命中结果写入一个文件（例如 `<run_dir>/secrets_guard_scan.txt`）；
         - 通过时也要写“PASS + scanned globs + patterns + target path”到该文件
         - 失败时：仍打印命中位置到 stderr，并 fail-loud

    2) 修改 `run_baseline.sh` 与 `run_edge_cases.sh`：
       - 在每次 run 完成证据落盘后调用 `rg_secrets_guard "$run_dir"`。
       - 将 `secrets_guard_scan.txt` 的路径写入 `run_meta.json`（如果脚本已有 meta），或至少确保文件存在并在 stderr 打印其路径。

    3) 确保 guard 不扫描 `logs/metrics.db*` 等文件（避免二进制扫描造成噪音）。
  </action>
  <verify>
    bash .planning/phases/11-runtime-validation/scripts/run_edge_cases.sh --help
  </verify>
  <done>
    - secrets guard 能扫描 artifacts 内的 `*.log`（不受 ignore 规则影响）
    - 每次 run 都会产出 `secrets_guard_scan.txt`，且报告可引用
    - guard 的匹配规则不会因 `sk-dummy` 等占位值误报
  </done>
