<task type="auto">
  <name>Task 1: ForwardStream 在 terminal error 时写入 RequestState.LastError</name>
  <files>sdk/api/handlers/stream_forwarder.go</files>
  <action>
在 `(*BaseAPIHandler).ForwardStream` 中，当收到 `errs` 的 terminal error（`*interfaces.ErrorMessage` 非 nil）时：

- 在调用 `opts.WriteTerminalError(...)` 与 `cancel(...)` 之前，尝试从 `gin.Context` 取出 request state（`metricsruntime.GetRequestState(c)`）。
- 若 state 存在且当前 `LastError` 为空，则写入一个“非空”的错误字符串：
  - 优先使用 `errMsg.Error.Error()`（当 `errMsg.Error != nil` 且非空）。
  - 否则使用 `http.StatusText(status)`，但仅当 `status >= 400` 时才允许用它。
    - `status` 来自 `errMsg.StatusCode`，当其 <= 0 时 fallback 500。
    - 当 `status` 落在 2xx/3xx（例如异常地给了 200）时，不要写入 `"OK"` 之类的文本；直接走固定 fallback 字符串。
  - 若 status text 仍为空，使用固定 fallback 字符串（例如 `"streaming terminal error"`）。
- 调用 `state.SetLastError(...)` 时，注意该 API 需要 `error`：对 fallback 字符串使用标准库 `errors.New(...)` 包装；不要把 nil 传进去。

覆盖两个 terminal error 分支：
- `case errMsg := <-errs:` 的直接错误路径
- `case chunk, ok := <-data:` 当 `data` 关闭后从 `errs` 拉取 pending terminal error 的路径

约束：
- 不要在 ForwardStream 内新增 feature flag / 兼容开关。
- 不要改变现有 flush 时机；只增加“写入 failure signal”的行为。
  </action>
  <verify>go test ./...</verify>
  <done>
- 任意 streaming terminal error 都会使 `RequestStateSnapshot.LastError` 变为非空
- 对于 `ErrorMessage.Error == nil` 的 terminal error 也会产生非空 LastError（使用 status text/fallback）
  </done>
